## ⚠️ 발견된 주요 문제점

### 1. 과도한 낙관론

**문제점**:
```
JazzFlow v2.0 예상 성능:
  복잡도(Perplexity): 12 (현재 15 대비)
  장르 인식률: 70%
  실시간 처리 속도(RTF): 1.5×
```

**현실**:
- ImprovNet: 360K + 318K 학습 단계 (총 678K)
- Magenta RT: 1.86M 학습 단계
- **JazzFlow 현재**: 학습 안 됨 (코드만 존재)

**개선안**:
```markdown
## 현실적인 기대치

### 1단계: 기본 버전 (첫 시도)
- 복잡도(Perplexity): 20-25 (첫 시도 기준)
- 장르 인식률: 50-60% (이진 분류)
- 실시간 처리 속도(RTF): 0.5-1.0× (최적화 전)

### 2단계: 최적화 버전 (3개월 후)
- 복잡도(Perplexity): 15-18
- 장르 인식률: 65-70%
- 실시간 처리 속도(RTF): 1.2-1.5×

### 3단계: 프로덕션 버전 (6개월 후)
- 복잡도(Perplexity): 12-15 (목표)
- 장르 인식률: 70-75%
- 실시간 처리 속도(RTF): 1.5-1.8× (하드웨어 최적화 포함)
```

### 2. 데이터셋 규모의 불일치

**문제점**:
```
ImprovNet: 1,400시간 (증강 포함)
Magenta RT: 190,000시간
JazzFlow v2.0: 200시간 MAESTRO
```

**현실 확인**:
- ImprovNet도 **1,377시간의 실제 데이터** 사용
- Corruption-Refinement는 데이터 증강이지만 **새로운 데이터를 생성하지 않음**
- 9가지 corruption 기법 = 9배 다양성, 하지만 **9배 데이터가 아님**

**개선안**:
```markdown
## 데이터 증강 현실 점검

### Corruption-Refinement가 실제로 하는 일:
- ✅ 모델 강건성 증가 (다양한 corruption 경험)
- ✅ 일반화 능력 향상 (섭동에 강함)
- ⚠️ 9배 데이터와 동등하지 않음 (같은 음악을 9번 보는 것)

### 실효 데이터 계산:
- 200시간 MAESTRO 원본 데이터
- 9가지 corruption 함수
- 실효 노출: ~600-800시간 (1,800시간 아님)
  - 이유: Corruption은 변형이지 독립 샘플이 아님
  - Corruption 유형 간 중복으로 고유성 감소

### 시사점:
- 더 다양한 기본 데이터 필요 (PiJAMA, 기타 소스)
- 또는 ImprovNet보다 낮은 품질 수용
- 또는 더 오래 학습하여 보완
```

### 3. 계산 복잡도 과소평가

**문제점**:
```
14주 로드맵:
  1-4주: 기초
  5-8주: 스트리밍
  9-10주: 통합
  11-14주: 고급 기능
```

**현실**:
- ImprovNet 학습: 360K 단계 사전학습 + 318K 미세조정
- Magenta RT 학습: 256개 TPU에서 1.86M 단계
- **각 단계마다 디버깅, 하이퍼파라미터 튜닝 필요**

**개선안**:
```markdown
## 현실적인 타임라인 (학술 환경)

### 1단계: 기초 (8주, 4주 아님)
1-2주차: Aria 토크나이저
  - 구현: 1주
  - 테스트 및 디버깅: 1주
  - 위험: 어휘 크기 문제, 청킹 버그

3-5주차: Corruption 함수들
  - 구현: 2주 (9개 함수는 간단하지 않음)
  - 테스트: 1주 (각 함수가 유효한 음악 생성하는지 확인)
  - 위험: 잘못된 조옮김이 화성 파괴

6-8주차: 학습 파이프라인
  - 설정: 1주
  - 첫 학습 실행: 1주 (실패 가능성 높음)
  - 디버깅 및 재학습: 1주

### 2단계: 스트리밍 (12주, 4주 아님)
9-12주차: MusicCoCa
  - 대조 학습용 데이터 수집: 2주
  - 모델 학습: 1주
  - 평가: 1주
  - 위험: 텍스트-오디오 정렬 품질

13-16주차: 스트리밍 아키텍처
  - 청크 기반 구현: 2주
  - SpectroStream 통합: 1주
  - 테스트: 1주

17-20주차: RTF 최적화
  - 프로파일링: 1주
  - 최적화 시도: 2주
  - 검증: 1주
  - 위험: 첫 시도에서 RTF ≥ 1× 달성 못할 수 있음

### 3단계: 통합 (6주, 2주 아님)
21-24주차: 시스템 결합
  - 통합: 2주
  - 버그 수정: 2주

25-26주차: 종단간 테스트
  - 위험: 구성요소 간 예상치 못한 상호작용

### 4단계: 고급 기능 (8주, 4주 아님)
27-30주차: 오디오 주입
  - 구현: 2주
  - 지연 시간 튜닝: 2주

31-34주차: 화성 제약 및 다중 작업
  - Logit 제약: 1주
  - 다중 작업 인터페이스: 2주
  - 사용자 테스트: 1주

### 총합: 34주 (8.5개월), 14주 아님
```

### 추론 (실시간 목표)

- RTX 4090 (24GB)

개발용: 클라우드 A100 사용 (시간당 $2-3)

## 종합 평가 프레임워크

### 객관적 메트릭 (필수)

**성능 메트릭**:
6. 음표 밀도 (5초당 음표 수)

   - 재즈: 30-40, 클래식: 20-35

7. 음 간 간격 (초)

4. 인간다움 (1-5 척도)

**재즈 전문 메트릭**:

   - 목표: 1.5-2.5 (재즈 스윙)

7. 코드-스케일 정렬 (%)
   - 화성 정확성
   - 목표: >70%

### 제어 메트릭 (하이브리드 모델용)

**스타일 전환 품질**:
8. 장르 분류기 정확도 (%)

### 6. 실패 케이스 분석 누락

**문제점**:
- 성공 시나리오만 논의
- 실패 가능성 및 대응책 부족

**개선안**:
```markdown
## 실패 모드 및 완화 전략

### 기술적 실패

**실패 1: RTF < 1.0× (실시간 미달성)**

발생 확률: 60% (첫 시도에서 가능성 높음)

증상:
- 생성 속도가 오디오 재생보다 느림
- 끊김, 출력 공백
- 연속 스트림 유지 불가

근본 원인:
- 하드웨어 대비 모델 너무 큼
- 비효율적인 RVQ 디코딩
- 메모리 병목

완화 방법:
1. 모델 크기 축소 (760M → 400M → 200M)
2. 더 작은 RVQ 깊이 사용 (16 → 8 레벨)
3. 디코더 최적화 (양자화, 가지치기)
4. RTF=0.5-0.8× 수용 (오프라인 전용)

**실패 2: 장르 전환 품질 저하**

발생 확률: 40%

증상:
- 장르 분류기 <50% 정확도
- 생성된 음악이 일반적으로 들림
- 재즈 스타일 인식 불가

근본 원인:
- 재즈 데이터 부족 (200시간 MAESTRO는 모두 클래식)
- 약한 corruption 함수
- 평균 스타일로 모델 붕괴

완화 방법:
1. PiJAMA 데이터셋 추가 (200시간 재즈)
2. Corruption 다양성 증가
3. 장르 특화 판별자 추가
4. 수동 검사 및 정성적 분석

**실패 3: 파국적 망각**

발생 확률: 30%

증상:
- 라이브 스트리밍 추가 후 corruption-refinement 성능 저하
- 다중 작업 성능이 단일 작업보다 나쁨

근본 원인:
- 충돌하는 학습 목표
- 불충분한 모델 용량
- 나쁜 학습 스케줄

완화 방법:
1. 모델 크기 증가 (400M → 600M)
2. 작업별 어댑터를 사용한 다중 작업 학습
3. 단계적 학습 (corruption 먼저, 그 다음 스트리밍)
4. 정규화 (EWC, PackNet)

**실패 4: 오디오 아티팩트**

발생 확률: 50%

증상:
- 클릭, 팝 소리
- 음높이 드리프트
- 리듬 불안정

근본 원인:
- 코덱 재구성 오류
- 청크 경계 불연속성
- RVQ 양자화 오류

완화 방법:
1. 청크 경계에서 오버랩-애드
2. 더 높은 RVQ 레벨 (16 → 24)
3. 후처리 필터
4. 더 나은 코덱 학습

### 데이터 실패

**실패 5: MAESTRO 과적합**

발생 확률: 70%

증상:
- MAESTRO 테스트 셋에서는 좋음
- 다른 데이터셋에 일반화 안 됨
- 학습 곡들 암기

근본 원인:
- 제한된 데이터 다양성 (200시간)
- 모두 클래식 피아노
- 기본 데이터에 장르 변화 없음

완화 방법:
1. 다양한 데이터셋 추가 (PiJAMA, WikiMIDI 등)
2. 더 강한 정규화 (드롭아웃, 가중치 감쇠)
3. Corruption 외 데이터 증강
4. 교차 데이터셋 평가

**실패 6: 재즈 데이터 부족**

발생 확률: 80% (가장 가능성 높음)

증상:
- 재즈 즉흥연주가 클래식처럼 들림

- **필요**: 조건당 n ≥ 20 (검정력=0.8, α=0.05, 효과 크기=0.5)

예제:
```python
from scipy.stats import ttest_ind
import numpy as np

# 사용자 평점 시뮬레이션 (1-5 척도)
improvnet_ratings = np.random.normal(3.5, 0.8, 20)
jazzflow_ratings = np.random.normal(3.2, 0.8, 20)

# 두 표본 t-검정
t_stat, p_value = ttest_ind(improvnet_ratings, jazzflow_ratings)

if p_value < 0.05:
    print(f"유의한 차이 있음 (p={p_value:.4f})")
else:
    print(f"유의한 차이 없음 (p={p_value:.4f})")

# 신뢰 구간
diff = improvnet_ratings.mean() - jazzflow_ratings.mean()
se = np.sqrt(improvnet_ratings.var()/20 + jazzflow_ratings.var()/20)
ci_lower = diff - 1.96*se
ci_upper = diff + 1.96*se
print(f"차이: {diff:.2f} [95% CI: {ci_lower:.2f}, {ci_upper:.2f}]")
```

### 유의성 검정

**모든 비교에 대해 다음을 보고**:
- p-값 (다중 검정 보정 포함)
- 효과 크기 (Cohen's d)
- 신뢰 구간

```python
from scipy.stats import wilcoxon, mannwhitneyu

# 대응 검정 (동일한 테스트 셋)
stat, p = wilcoxon(improvnet_scores, jazzflow_scores)

# 비대응 검정 (다른 테스트 셋)
stat, p = mannwhitneyu(improvnet_scores, jazzflow_scores)

# 효과 크기
def cohens_d(x, y):
    nx, ny = len(x), len(y)
    var_x, var_y = np.var(x, ddof=1), np.var(y, ddof=1)
    pooled_std = np.sqrt(((nx-1)*var_x + (ny-1)*var_y) / (nx+ny-2))
    return (np.mean(x) - np.mean(y)) / pooled_std

d = cohens_d(improvnet_scores, jazzflow_scores)
print(f"효과 크기 (Cohen's d): {d:.2f}")

# 해석:
# |d| < 0.2: 작음
# |d| < 0.5: 중간
# |d| < 0.8: 큼
# |d| ≥ 0.8: 매우 큼
```
